# Реестр рисков и уточнённый план Tumbler

**Статус:** Этап 0. Дополняет: tumblr-2012.md, open-source-review.md, decisions.md.

## 1. Реестр рисков

Вероятность/влияние: Н — низкая, С — средняя, В — высокая.

| # | Риск | В | В | Митигация |
|---|---|---|---|---|
| 1 | **Точность воссоздания дашборда**: залогиненный HTML 2012 в архиве отсутствует | В | С | CSS/спрайты/промо-скриншоты 2012 уже добыты (tumblr-2012.md); неясные места помечены [Р]; на этапе 3 — визуальная сверка со скриншотами Web Design Museum |
| 2 | **Копирайт на ассеты**: спрайты/логотип Tumblr защищены | С | В | Скачанные материалы — только референс для нас; в код не включаются; все иконки и логотип — собственные SVG (ADR-017) |
| 3 | **Русский поиск**: FTS5 не умеет русские словоформы | В | С | unicode61 + префиксные запросы (`пост*`) + LIKE-фолбэк (<3 симв.); ограничение зафиксировано в документации, не маскируем |
| 4 | **Большие/вредоносные медиа** (GIF-бомбы, видео) | С | В | Настраиваемые лимиты (settings), file-type + sharp-валидация, GIF-метаданные (число кадров/размер) до принятия, rate limit загрузок, обработка вне транзакций БД |
| 5 | **Multer-подобные CVE в зависимостях** (история 2025) | С | С | Версии зафиксированы ≥2.5; проверка `npm audit` + OSV на каждом этапе; зависимости минимальны |
| 6 | **SQLite concurrency** при росте нагрузки | Н | С | WAL, один процесс, короткие транзакции; признаки миграции на PG описаны в ADR-003 |
| 7 | **Планировщик**: дубли или потеря постов при рестарте/простое | С | В | Атомарный захват в транзакции (status-переход), догон пропущенного при старте, идемпотентная публикация; автотест «рестарт в момент публикации» (этап 7) |
| 8 | **Пользовательский CSS** как вектор атаки | С | В | Только страница публичного блога; CSP `script-src 'self'`; санитизация @import/url(javascript:); системные экраны CSS пользователя не получают; проверка на этапе 8 |
| 9 | **Анонимный ask-спам** | В | С | Rate limit по IP+сессии (~5/час, настраиваемо), выключатель ask и анонимности у владельца; капча — только при реальной необходимости |
| 10 | **AGPL/GPL-заимствования** | Н | В | Код платформ-референсов не копируется; зависимости только MIT/Apache/ISC/BSD; проверка лицензий перед добавлением любой зависимости |
| 11 | **Дрейф эстетики** в современный SaaS-вид при имплементации | С | С | design-spec.md — обязательный чек-лист этапа 3; запрет скруглений/теней сверх токенов; визуальная сверка со скриншотами 2012 |
| 12 | **Wayback Machine нестабилен** (файлы иногда не отдаются) | С | Н | Ключевые факты уже извлечены и записаны в tumblr-2012.md; градиент шапки — единственный пробел, помечен [Р] |
| 13 | **Один блог на аккаунт** может оказаться тесным (ТЗ фиксирует) | Н | Н | Схема это учитывает: `blogs.user_id UNIQUE` — снятие ограничения в будущем = миграция, не переписывание |
| 14 | **Часовые пояса** в планировании | С | С | UTC везде (ADR-011/013), timezone в профиле, тесты на граничные случаи (перевод часов, полночь) |
| 15 | **Бесконечная лента и порядок постов** при подгрузке | С | С | Пагинация по курсору (published_at+id), порядок строго хронологический, тест на дубликаты |

## 2. Неопределённости (осознанные пробелы исследования)

1. Градиент шапки 2012 — картинка из архива не скачалась; берём реконструкцию `#3a5a77 → #2c4762`, сверить на этапе 3.
2. Мобильный дашборд 2012 не сохранился — мобильная версия проектируется как авторская реконструкция в той же системе токенов (design-spec §6).
3. Точный вид composer-форм раскрытия (по типам) — известен общий каркас, детали форм реконструированы по промо-скриншотам.
4. Лицензии Wafrn и New XKit не подтверждены (лимит GitHub API при исследовании) — некритично: код этих проектов не используется.

## 3. Уточнённый план этапов (базируется на дорожной карте ТЗ, раздел 10)

| Этап | Содержание | Критерий готовности |
|---|---|---|
| 1. Каркас | Node 24, Express 5, better-sqlite3@13 + WAL, миграционный раннер, config.env, error-handler, `/health`, README | Чистая установка по README: `npm ci && npm run migrate && npm start` — сервер отвечает; тесты миграций зелёные |
| 2. Аккаунты и блоги | Регистрация/логин/выход, argon2id, сессии в SQLite, CSRF, один блог/аккаунт, slug, публичная страница блога для гостя, каркас i18n | Регистрация, дубликат email, выход из всех сессий, гость видит блог — автотесты; чужой user_id в запросе игнорируется |
| 3. Дизайн-система | Токены design-spec, шапка, дашборд-каркас, композер-карточка, публичный блог, адаптив 3 брейкпоинта, все состояния | Визуальная сверка со скриншотами 2012; мобильная ширина без горизонтального скролла |
| 4. Посты и медиа | 7 типов (вкл. отдельный GIF), CRUD, черновики, предпросмотр, Storage-абстракция, валидация файлов, лимиты | Сквозной тест каждого типа: создание → сохранение → отображение в ленте и блоге; загрузка .exe с расширением .gif отклоняется |
| 5. Социальное | Follow/like/reblog (с текстом)/comments, счётчики, пустые состояния, гостевые подсказки | Сценарий двух аккаунтов из критериев приёмки ТЗ; дубликаты лайк/фолллов невозможны (PK) |
| 6. Поиск и Ask | FTS5-индексы, поиск постов/блогов/тегов, фильтр по типу, ask + анонимные + rate limit | Поиск находит по частичному слову; ask-цикл «вопрос → ответ постом» проходит |
| 7. Планировщик и уведомления | Очередь/расписание, тикер, догон после рестарта; уведомления 6 типов, непрочитанный счётчик | Тест: запланированный пост публикуется ровно один раз при рестарте сервера в момент публикации |
| 8. Модерация | Жалобы, блокировки, NSFW, админка, журнал, лимиты в settings | Роль проверяется на сервере (тесты 403); каждое действие модератора в журнале |
| 9. API и статистика | `/api/v1` по всем модулям, OpenAPI, счётчики просмотров, агрегаты | Спека совпадает с поведением (тест по OpenAPI); статистика без персональных данных |
| 10. Тесты и деплой | Автотесты E2E, security-ревизия, backup/restore SQLite+uploads, VPS-гайд, production-config | Чистая установка + backup/restore проверены на реальных данных; отчёт только по реально выполненным проверкам |

Правило ТЗ сохраняется: после каждого этапа приложение запускается и проходит проверки; базовый сценарий этапа не работает — дальше не идём.

## 4. Решения, требующие подтверждения владельцем (одобрение исследования)

1. Принять рекомендуемый стек (ADR-001…020) — альтернативы описаны в open-source-review.md.
2. Принять базу палитры #2C4762 + брендовый #36465D (токены design-spec §2).
3. Принять анонимные Ask по модели Tumblr (ADR-018) — ТЗ делегировало решение исследованию.
4. Подтвердить: chat-пост из оригинального Tumblr 2012 **не** реализуем (ТЗ фиксирует 7 типов с GIF вместо chat).
